## ЛЕКАРСТВО №3: ЩЕЛЧОК ПРИ АТАКЕ НОТЫ (v1.4.23 «ANTI-CLICK»)

### Симптом
- При взятии ноты звук «проскакивает» — звучит выше своей громкости.
- Характер: короткий щелчок на частоте выбранной ноты.
- Проявлялся в режимах CHIP-TUNE и MIDI GM.
- SOUNDFONT (SF2) не страдал — «из-за внутренней задержки, встроенной в сам шрифт».
- Десктопный 6-часовой прогон баг не ловил. Ловил только тач-этап на телефоне/планшете.

### Диагноз: баг жил НЕ в нашем коде
Адрес негодяя: `audioCtx.currentTime` в состоянии `suspended`.

Механизм:
1. AudioContext спит (`suspended`) — его `currentTime` ЗАМОРОЖЕН, время не идёт.
2. Нота берётся в этот момент: конверт атаки скедулится на `currentTime + 0.005`.
3. Вызывается `resume()` — контекст просыпается асинхронно и ДОГОНЯЕТ реальное время.
4. События атаки оказываются в прошлом. Браузер не отбрасывает их, а применяет
   мгновенно: 5 мс нарастания сжимаются в ступеньку.
5. Волна прыгает с нуля амплитуды на полный пик за один сэмпл — это и есть щелчок.

Объяснение всех странностей:
- «выше громкости» — пик ступеньки слышен как отдельный импульс поверх ноты;
- SF2 невиновен — у сэмплов своя мягкая атака и микрозадержка старта, контекст
  успевает проснуться до громкой части звука;
- долгий десктопный прогон молчал — контекст не спал, сжиматься было нечему;
- баг «возвращался» после фиксов — мы укрепляли наш дом, а он жил у соседей
  (на границе сущностей: наш код + чужой сервис + время).

### Лекарство (слой v1.4.23)
1. Ядра старта нот переименованы: `chipOnCore` / `sfOnCore` / `midiOnCore`.
2. Сверху — обёртки через единый `startCtx`:
   - контекст `running` -> ядро стартует мгновенно, нулевая цена;
   - контекст `suspended` -> `resume()`, ядро запускается по `statechange`
     со страховкой 400 мс — нота не теряется ни при каком раскладе.
3. Прореквизиты (слой v1.4.22, работает вместе): `latencyHint: 'interactive'`,
   телеметрия контекста в журнал (sampleRate / baseLatency / смена состояний),
   автоwake на pointerdown/keydown/touchstart.

### Тест-провокатор (для повторной проверки в будущем)
Свернуть окно / заблокировать экран телефона -> развернуть -> сразу сыграть ноту.
Атака должна быть чистой. Журнал покажет `AUDIO: контекст → suspended/running`
на каждый переход.

## ЛЕКАРСТВО №2: ПОЖИРАТЕЛЬ КОДА — НЕЗАКРЫТЫЙ КОММЕНТАРИЙ (v1.4.20)

### Симптом
После правок часть кода молча перестаёт работать: `susMode`/`susTimers` не объявлены,
панель мертва, при этом «синтаксически всё почти в порядке».

### Диагноз
Маркеры-комментарии вида `/* v1.4.19: ...` были оставлены БЕЗ закрытия `*/`.
JavaScript не считает это ошибкой: парсер легально глотает всё до ближайшего
чужого `*/` — часто за сотни строк, вместе с живым кодом между ними.
Отсюда название «пожиратель»: он ел куски кода между маркером и чужим закрытием.

### Лекарство
- Каждому маркеру — СВОЁ закрытие сразу после текста: `/* v1.4.20: ... */`.
- Маркер-комментарий — это исполняемый для парсера код, а не украшение.
- В автопроверки встроен честный строко-осведомлённый лексер: отличает `/* */`
  от `//`, учитывает строки в кавычках и regex-литералы, проверяет ПАРЫ.
  Порядок проверок: комментарии -> скобки -> сверка якорей DOM.

## ЛЕКАРСТВО №1: pointer-events: none НА ИНТЕРАКТИВНЫХ ЭЛЕМЕНТАХ

### Симптом
Элемент визуально жив, но клики по нему не работают или проваливаются ниже.

### Диагноз и лекарство
`pointer-events: none` снимает элемент с приёма событий: клик проходит сквозь него
к элементу под ним. ЛЕГАЛЬНО — только для декораций (`body::after`) и подписей
(`.lbl`), когда клик ДОЛЖЕН пройти сквозь к клавише. НЕЛЬЗЯ — на клавиши, кнопки,
бегунки. Аудит правок CSS — обязательный шаг перед сборкой.

4. Журнал движка — телеметрия вместо гадания.
